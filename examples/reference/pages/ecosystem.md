# One Preset Controls Typography, Color, and Motion

Each of six presets generates `tokens.css` + `theme.css`.

<v-clicks>

- **editorial-dark** — Playfair Display + Source Sans 3. Near-black bg, cool accent. Serious, high-trust. Fades only.
- **swiss-minimal** — Plus Jakarta Sans + Figtree. White bg, restrained accent. Precise, calm. Two transitions max.
- **bold-modern** — Bebas Neue + DM Sans. Dark bg, bright accent pair. Assertive, energetic. Uses iris and zoom.
- **tufte-data** — EB Garamond + Source Sans 3. Cream `#fffff8`, data-blue `#2d5f8a`. Scholarly, dense. Sidenote margin layout.
- **cloudflare** — Inter + JetBrains Mono. Warm cream `#fffbf5`, orange `#ff4801`. Workshop-ready. Full transition vocabulary.
- **material-design** — Outfit + Plus Jakarta Sans. M3 surface `#FFFBFE`, primary `#6750A4`. Systematic. M3 easing curves.

</v-clicks>

# Every Deck Ships With Seven Scaffold Files

Generated by `new-deck.py`, present in every deck.

<v-clicks>

- **setup/shortcuts.ts** — Registers `?` (help overlay) and `p` (presenter mode) keyboard shortcuts
- **composables/useHelp.ts** — Reactive `showHelp` state shared between shortcuts and the help component
- **components/KeyboardHelp.vue** — Full-screen shortcut overlay using `--deck-accent` and `--deck-font-*` tokens
- **global-top.vue** — Mounts KeyboardHelp when `showHelp` is true
- **global-bottom.vue** — Footer with slide number and title, hidden on cover/end layouts
- **setup/mermaid-renderer.ts** — Beautiful Mermaid rendering with deck palette tokens injected automatically
- **styles/transitions.css** — 12 cinematic CSS transitions imported by `styles/index.css`

</v-clicks>

# deck.spec.md Is the Planning Schema

Seven sections define intent before a single slide is written.

<v-clicks>

- **Meta** — title, purpose, audience, tone, target-length, style-preset
- **Source Materials** — documents digested to produce the deck (project decks only)
- **Through-Line** — the conceptual thread: type, concept, and which slides it surfaces in
- **Design Tokens** — colors, typography, spacing, motion as semantic variables
- **Layout System** — preferred builtins, custom layouts, components, CSS files
- **Slides** — per-slide kind, layout, title, body, notes, and source citations
- **Notes Policy** — optional presenter notes guidelines and asset rules

</v-clicks>

<!-- deck.spec.md is the planning schema for a Slidev deck project. It captures intent, not implementation. The spec must be human-readable and deterministic enough to compile into a working deck.

[click] Meta — required fields: title, purpose, audience, tone, target-length, style-preset. Optional: project-url (triggers source gathering and project color extraction), subtitle, author, date.

[click] Source Materials — project decks only. Lists at least 2 documents digested to produce the deck: readme, changelog, architecture, lessons-learned, screenshots, specs, research. Each with a path and parenthetical summary.

[click] Through-Line — the conceptual thread. Types: metaphor, question, concept, provocation, design-rule. Must appear in at least 3 slides, ideally 5-6, gaining new meaning each time. Not a tagline — an analytical instrument.

[click] Design Tokens — semantic variables for colors (bg, fg, accent, muted), typography (display, body, mono), and motion (preset name). Keep token count low. Avoid slide-specific tokens.

[click] Layout System — prefer-builtins: true. Lists which builtins, custom layouts, components, and CSS files the deck needs. Every listed custom layout must be used. Every listed component must be justified.

[click] Slides — each is a ### Slide N block. Required: kind, layout, title. Optional: subtitle, body, left, right, media, image, alt, notes, sources, component, props. No giant HTML blobs.

[click] Notes Policy and Update History are optional sections for governing presenter notes and tracking spec revisions.

# Four Progress Indicators Show Where You Are

Set `progress:` in deck.spec.md Meta. The compiler mounts the chosen component automatically.

<v-clicks>

- **segment-bar** — Thin 3px bar at the top with one segment per section. Current section fills with accent color.
- **dot-rail** — Vertical column of dots on the right edge. Current dot filled with accent. Best for 5-15 slides.
- **tally-marks** — Analog-style stroke marks at the bottom. Every 5th mark crosses diagonally. Best under 20 slides.
- **arc-gauge** — Quarter-circle SVG in the bottom-right corner that fills clockwise. Works at any length.

</v-clicks>

<!-- Progress indicators are optional visual cues that orient the audience within the deck. Set the progress field in deck.spec.md's Meta section to enable one. The compiler copies the chosen component into the deck and mounts it in global-top.vue or global-bottom.vue. All four use var(--deck-*) tokens and hide on cover/end layouts.

[click] segment-bar — positioned at the top of the slide. A thin 3px bar divided into one segment per section. The current section fills progressively with the accent color. Default for most presets.

[click] dot-rail — positioned on the right edge. A vertical column of small dots where the current slide's dot is filled with accent. Best for focused talks of 5 to 15 slides.

[click] tally-marks — positioned at the bottom. Analog-style stroke marks rendered in groups. Every 5th mark crosses diagonally like a traditional tally. Best for decks under 20 slides with editorial or tufte presets.

[click] arc-gauge — positioned in the bottom-right corner. A quarter-circle SVG arc that fills clockwise as the deck progresses. Compact and works at any deck length.

Preset defaults: editorial-dark, swiss-minimal, bold-modern, cloudflare, and material-design all default to segment-bar. tufte-data defaults to tally-marks. Setting progress: none disables the indicator entirely.

Sources:
